# README.md: Пайплайн предобработки данных (Уровень B)

## 1. Описание задачи и данных
Цель проекта — создание изолированного пайплайна предобработки разнородных данных (числовых и категориальных признаков) с использованием инструментов `scikit-learn` (`ColumnTransformer`, `Pipeline`). Пайплайн решает задачи обработки пропущенных значений, масштабирования признаков, кодирования категорий и предотвращения утечки обучающих данных (data leakage).

Набор данных включает в себя следующие признаки:
* **Числовые:** `age` (возраст), `salary` (зарплата).
* **Категориальные:** `city` (город), `gender` (пол).
* **Целевой признак:** `target` (бинарный).

---

## 2. Обоснование стратегий предобработки

### А. Числовые признаки (`age`, `salary`)
* **Заполнение пропусков (`SimpleImputer(strategy='median')`):**
  * Для возраста (`age`) и особенно заработной платы (`salary`) выбрана стратегия заполнения **медианой** вместо среднего арифметического. 
  * *Обоснование:* Распределения таких величин, как доход, часто имеют правостороннюю асимметрию и содержат выбросы (аномально высокие значения). Медиана устойчива к выбросам, тогда как среднее значение сильно смещается под их влиянием.
* **Масштабирование (`StandardScaler`):**
  * Переводит значения в единый масштаб со средним `0` и стандартным отклонением `1`. Это критически важно для метрических алгоритмов (k-NN, SVM) и линейных моделей.

### Б. Категориальные признаки (`city`, `gender`)
* **Заполнение пропусков (`SimpleImputer(strategy='constant', fill_value='missing')`):**
  * Пропуски выделяются в **отдельную категорию** `'missing'`.
  * *Обоснование:* Пропуск в категориальных данных может нести скрытый смысл (например, нежелание пользователя указывать пол или отсутствие информации о городе). Заполнение самой частой категорией (модой) может исказить реальную структуру данных и логику взаимосвязей.
* **Кодирование (`OneHotEncoder(handle_unknown='ignore', sparse_output=False)`):**
  * Категориальные значения преобразуются в бинарные разреженные столбцы.
  * *Обоснование:* Применение One-Hot кодирования подходит для номинальных признаков без естественного порядка. Флаг `handle_unknown='ignore'` гарантирует, что при появлении новых категорий на этапе тестирования пайплайн не выдаст ошибку, а просто закодирует их нулями.

## 3. Архитектура пайплайна (`ColumnTransformer`)
Для параллельной и независимой обработки разнотипных колонок собран `ColumnTransformer`:
```python
preprocessor = ColumnTransformer(
    transformers=[
        ('num', num_transformer, num_cols),
        ('cat', cat_transformer, cat_cols)
    ]
)
```
Это решение позволяет лаконично упаковать все шаги трансформации в единый объект, который можно использовать совместно с моделями машинного обучения.

---

## 4. Контроль отсутствия утечки данных (Data Leakage)
Утечка данных происходит, когда информация из тестового набора используется при настройке параметров предобработки (например, расчет среднего, медианы или стандартного отклонения).

Для предотвращения утечки реализован следующий строгий регламент:
1. Данные разделяются на обучающую (`train`) и тестовую (`test`) выборки до начала любых трансформаций.
2. Вызов метода **`fit_transform()`** производится исключительно на обучающей выборке (`X_train`). На этом этапе пайплайн вычисляет медианы и параметры масштабирования для `train`.
3. Вызов метода **`transform()`** применяется к тестовой выборке (`X_test`). На этом этапе используются параметры (медианы, масштабы, категории), вычисленные ранее на `train`.

### Результат проверки
* Сравнительный анализ размерностей матриц после обработки подтверждает корректность работы пайплайна:
  * Количество признаков в обучающем и тестовом наборах строго совпадает.
  * Модель защищена от получения скрытой информации из будущего теста.
